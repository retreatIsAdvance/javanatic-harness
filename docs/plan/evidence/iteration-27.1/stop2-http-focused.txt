## 5. 附注

- 停 2 边界：只跑 MCP 三模块聚焦矩阵 + validate（计划「停 2 取证」口径）；
  全量 package / consumer / jlink 属停 3 收口。
- 停 1 已登记偏离 D2（`bundle/base` 与 `examples/headless` 未挂 `mcp-registry`
  行 → 装配测试预期红）仍成立；停 3 补两行后转绿，本停点未改消费面。
- JDK HttpClient 已知坑的落地：`HttpRequest.timeout` 只覆盖响应头阶段，正文另由
  `BodyGuard` 看门狗按流关闭收口；JDK 自带 `HttpTimeoutException` 与看门狗同归
  「超时」档（`McpTimeoutException`），**不失效会话、不触发重连**——由
  `timeoutFailsCall` 的 `state == CONNECTED` 断言钉死。
- SSE 帧帽按 UTF-8 字节累计（多行 `data:` 之间计换行），防「每行在行帽下、事件
  无界累计」绕过；HTTP 响应体帽与单事件帽同用 `MAX_FRAME_BYTES = 8 MiB`。
- 分页两条用例在夹具增补 `--pages` / `--endless-pages` 后补入，覆盖 stdio 既有
  分页平价（合并顺序 / 页帽 fail loud）。
- 响应体停顿夹具 `--stall-body-once <marker> <ms>` 采用 **chunked**（`sendResponseHeaders
  (200, 0)`）：先写半个 JSON 再停。定长 Content-Length 在 M7 变异下会让服务端无限等
  客户端读、测试挂起；chunked 在停顿后写尾段并关流，变异被干净地暴露为「畸形响应 +
  耗时超限」，而不是挂起。正常路径则由看门狗 1s 关流收口。
