== 2. landlock 硬门（CI 第 6 步形状）真跑：负支路 ==
$ docker exec <build> bash -c 'set -o pipefail; img=/src/dist/jh/target/jlink-image; \
    "$img/bin/java" -XX:-UsePerfData --enable-native-access=io.javanatic.harness.sandbox.local \
    -m io.javanatic.harness.sandbox.local/io.javanatic.harness.sandbox.local.LandlockExecMain --probe'
landlock: unavailable — landlock syscalls not present (errno ENOSYS)
PROBE-EXIT=10
$ uname -r ; head -1 /proc/version
6.4.16-linuxkit
Linux version 6.4.16-linuxkit (root@buildkitsandbox) (gcc (Alpine 12.2.1_git20220924-r10) 12.2.1 ...
# 判读：
#  - 命中 Landlock.EXIT_UNAVAILABLE(10) 分支；结论行出自 absentReason() 的 ENOSYS 档（Landlock.java:416）。
#  - ENOSYS 而非 EPERM ⇒ **syscall 444 抵达了内核**（seccomp 拦截给的是 EPERM 类错误码）。
#    ⇒ 「容器默认 seccomp 是否放行 landlock 系统调用」这一待验项，本机给出可判别事实：放行。
#  - 与 S-a-local-kernel-probe.txt 一致：该内核未编译 CONFIG_SECURITY_LANDLOCK。
#  - 诊断三分档（ENOSYS / EOPNOTSUPP / 其他 errno）在本机拿到 ENOSYS 档实样。
# 边界：正支路（ABI≥3 真建真限真拒写）需 landlock 内核，仍属 CI 首跑。

== 4. INFO 支路真跑（bwrap 可用档） ==
$ docker run --rm <build-img> sh -c 'bwrap --ro-bind / / --dev /dev /usr/bin/true; echo EXIT=$?'
bwrap: Creating new namespace failed: Operation not permitted
EXIT=1
$ docker run --rm --security-opt seccomp=unconfined <build-img> sh -c '...同上...'
bwrap: Creating new namespace failed: Operation not permitted       （放宽 seccomp 仍不行）
$ docker run --rm --privileged <build-img> sh -c '...同上...'
EXIT=0                                                              （容器需被给足命名空间权限）
$ docker run --rm --privileged -e LANG=C.UTF-8 -v <target>:/drop:ro -w /tmp <build-img> \
    sh -c '/drop/jlink-image/bin/jh --verify; echo "VERIFY-EXIT=$?"'
INFO: sandbox: confining policy "workspace-write" is enforced by backend "bwrap" (enforcement FULL)
Profile: headless   policy: STANDARD
  ...
VERIFY-EXIT=0
# 判读：CI 第 8 步的 grep 串（生产文本 AppBoot.java:256 原样）在本机真 Linux 内核上逐字节命中。
# 副产品（it25 相关事实）：容器内 bwrap 常态不可用（默认档与 seccomp=unconfined 都不行，需 --privileged）；
#   而 landlock 是内核级能力、不经 userns。容器场景下 landlock 腿是主力。

== 8. 诚实边界与两条待裁观察 ==
仍属「首次 CI 跑」的事实：
  - actions/upload-artifact 取件（0.2.0 发布面）；
  - landlock **正**支路（ABI≥3 真建真限真拒写）——本机内核缺席，只能验负支路；
  - CI 产物为 amd64、本机归档为 aarch64（形状/命名/profile 同源，非同一次构建）。
两条观察（未改码，留待裁决）：
  1. 非 UTF-8 locale 下 CLI 输出整体降级：同一命令，无 LANG → "Javanatic Harness headless runner
     ?? ??????????(REPL)"，LANG=C.UTF-8 → 中文正常（本次两渲染均已实跑）。
     影响面：裸容器/极简镜像这类默认 ASCII locale 的环境（正是「干净 Linux」验收场景）。
     出路候选：启动器注入 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8（dist/jh 的 launcher
     目前无 options 位，需另寻挂点），或在文档注明「非 UTF-8 locale 下请设 LANG」。
  2. 结论行的 em-dash 与链诊断分隔符在非 UTF-8 locale 下同源降级为 "?"（英文骨架不受影响，
     CI 的两处 grep 断言不受影响）。字节级实证（同一归档、同一命令，仅 locale 不同）：
     $ <bin/jh> --verify 2>&1 | grep -o "exit 10 .\{0,14\}" | od -c
       A 无 LANG       e x i t   1 0   ?   l a n d l o c k :   u n      （单字节 0x3f）
       B LANG=C.UTF-8  e x i t   1 0   342 200 224   l a n d l o c k :（U+2014 的 UTF-8 三字节）
     整行字节数：A=402 / B=406（两处 em-dash 各 +2 字节，与降级位置数一致）。
