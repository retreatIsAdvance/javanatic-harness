== 5. 步骤 7 断言的本地三分支演习（脚本与 ci.yml 内嵌同源，dry-run 真跑） ==
$ python3 /tmp/sc-blocks/assert-leg.py <surefire XML>          # 判定体逐字取自步骤 7

(a) 负分支（本机真 XML：darwin 上两条 linux 腿被平台分区跳过）——必须红：
landlock leg not really run: missing=[] skipped=['landlockReadOnlyDeniesRealWriteWithDialectMarker', 'landlockWorkspaceWriteAllowsInsideAndDeniesOutside']
EXIT=1

(b) 正分支（同 XML 剥掉 <skipped/> 模拟 Linux 全跑；testcase 计数不变 23==23）——必须绿：
landlock e2e ran for real: landlockReadOnlyDeniesRealWriteWithDialectMarker, landlockWorkspaceWriteAllowsInsideAndDeniesOutside
EXIT=0

(c) 缺测试分支（正分支 XML 里删掉一条 landlock 用例）——必须红：
landlock leg not really run: missing=['landlockWorkspaceWriteAllowsInsideAndDeniesOutside'] skipped=[]
EXIT=1
# 三分支＝「静默跳过不算绿」的三种失败面（跳/缺/正常）都被断言抓住；本机可验部分到此为止，
#   真 runner 上的落点（ABI≥3 + seccomp 放行）归第 8 节的首次 CI 跑。

== 8. 本机不可验边界（如实标注；首次 CI 跑后回填去向） ==
- 步骤 6 landlock 硬门能否在 runner 上通过：取决于 runner 内核 ABI≥3 与 sysctl/AppArmor 面——本机无
  landlock 内核（S-a-local-kernel-probe.txt 已实探），不可预验；CI 首跑结论若有偏差，按「回填」惯例补记。
- 步骤 9 容器内 `--verify` 的两分支（landlock 可用 ⇒ INFO / 全败 ⇒ WARNING）与 docker 默认 seccomp 对
  landlock 系统调用的放行情况：不预设、看日志；本机 docker.io 不可达（it24 实探），容器验不可本地复现。
- 步骤 10 upload-artifact：仅 CI 环境可验（本地非 CI 无 artifact 服务）。
- 05 §6 新记的 landlock `/dev/null` 写被拒（EACCES）：allow-list 语义的直接推论（写效果不在
  任何可写根之下即拒），本机无 landlock 内核不可实测——已在 05 与台账同步标注；Linux 腿真跑后
  可顺手复核该推论（不必为它单开用例）。
- 三条均为**机械性事实**，不改变 S-c 的文档/定义面结论；首次 CI 跑（需 push 放行）后本节改为回填记录。
