== 4. JUL 流绑定探针（修正表缺陷的实证） ==
# 源文件随证据入库：docs/plan/evidence/iteration-24/S-b-jul-err-binding-probe.java（未参与构建）
$ java docs/plan/evidence/iteration-24/S-b-jul-err-binding-probe.java      （连跑 3 次，逐次同形）
first-captured=true second-captured=false second-received-first-line=false
first-captured=true second-captured=false second-received-first-line=false
first-captured=true second-captured=false second-received-first-line=false
EXIT=0（逐次）
# 结论：JUL 后端在**首条记录发布时**一次性绑定彼时的 System.err；发布后再 setErr 的新流收不到任何记录，
#   旧流继续收。故 stderr 捕获式断言只对「本 JVM 的首条发布」可靠（同 JVM 内成对捕获必有一方捕空）——
#   验证 --verify 双级观测改走包私有出口 AppBoot.emitSandboxObservations(root, sink)；生产出口仍 LOG::log，
#   真实 stderr 面由第 3 节真镜像双腿覆盖。
