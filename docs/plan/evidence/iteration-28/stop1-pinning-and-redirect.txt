## 1. TOCTOU 闭合的四条可观测性质

实现：`resolve` 每跳一次 → `gate.verify` 整组 → 循环 `plain.connect(new InetSocketAddress(address, port))`
→ `SSLSocketFactory.createSocket(plain, urlHost, port, true)`（SNI/endpoint identification 用 URL 主机，
TCP 目标保持钉住）→ 期间不再解析。

| 性质 | 用例 | 断言（测试文件行号） |
|---|---|---|
| 每跳解析恰一次 | `pinsAddressAndSendsOnlyFixedHeaders` | `resolver.calls() == ["pinned.test"]`（:58） |
| 解析结果整组过闸 | 同上 | `gate.calls() == ["pinned.test=1"]`（:59） |
| TLS 用 URL 主机名而非地址 | 同上 | 服务端 SNI 观察 `["pinned.test"]`（:60）；Host 头 `pinned.test:<port>` |
| 字面 IP 不回落解析器、但仍过同一闸 | `literalIpSkipsResolverButStillGoesThroughGate` | resolver 被设为“调用即 AssertionError”，实际零调用；`gate.calls() == ["127.0.0.1=1"]`（:88）；无 SNI（:89） |
| 连接目标 == 解析返回地址 | 全部真跑用例 | 夹具只监听 `127.0.0.1`；解析器返回回环；请求实际到达（每例请求/正文断言） |
| endpoint identification 用 URL 主机 | `hostnameVerificationFailureIsNetworkError` | `mismatch.test` 解析到回环（证书 SAN 含 `ip:127.0.0.1` 但不含该名）→ 握手失败 `WEB_NETWORK_ERROR`，消息含 `mismatch.test`（:127） |
| 多答案任一非公网 → 连之前整组拒 | `anyNonPublicAnswerRejectsWholeSetBeforeConnecting` | 答案 `[93.184.216.34, 10.0.0.1]`（公网在前）→ `WEB_BLOCKED_ADDRESS`、消息含 `10.0.0.1`、夹具零请求；resolver 恰一次（:112） |

请求面固定头只含 `Host`/`User-Agent`/`Accept`/`Accept-Encoding: identity`/`Connection: close`；
用例断言 `Cookie`/`Authorization`/`Referer` 均为 null（:65-:70），并断言 `Accept` 精确值。

## 2. 重定向逐跳复验

| 性质 | 用例 | 证据 |
|---|---|---|
| 跨源逐跳：URL 策略 + 重新解析 + 重新过闸 + 重新钉地址 | `followsCrossOriginRedirectWithPerHopResolutionAndNoForwardedHeaders` | resolver 恰 `["pinned.test", "second.test"]`（:165）；gate 恰两跳各一次（:166）；第二跳 Host/SNI = `second.test`；无转发头 |
| 相对 Location 以当前 URL 为基准 | `followsRelativeRedirectOnSameOrigin` | `/a` → `/b`，最终 URL 与正文正确 |
| 301/302/303/307/308 一律按 GET 重发 | `followsAllRedirectStatusesAsGet`（参数化 5 例） | 第二请求行 `GET /next HTTP/1.1`（:142）；最终 200 |
| https→http 降级拒绝 | `rejectsRedirectDowngrade` | `WEB_REDIRECT_BLOCKED`，且只有首跳一次请求（未发出明文请求） |
| 缺 Location 拒绝（不把 302 当普通结果） | `rejectsRedirectWithoutLocation` | `WEB_REDIRECT_BLOCKED`，消息含 `Location` |
| ≤ 5 跳 | `stopsAfterFiveRedirects` | 第 6 个 3xx 处 `WEB_REDIRECT_BLOCKED`，消息含 `5`；请求数 6 |
| 坏/缺/空 Location、`javascript:`、坏方括号 | `FetchUrlPolicyTest#badOrMissingLocationIsBlocked` | 全部 `WEB_REDIRECT_BLOCKED`（见 `stop1-fetch-policy.txt`） |

注：实现中 `resolveRedirect` 在重定向分支内调用，**先于正文读取与内容类型检查**；3xx 的正文不进入
内容白名单判定，但缺 Location 不再被当作可返回的结果（本停点修正）。

## 4. 残余（交评审）

- **DNS 解析期间的总截止/取消不可强制**：解析一次是 TOCTOU 闭合的前提，但系统 resolver 的阻塞
  不能被 `AbortSignal` 唤醒；连接/握手/读写均受剩余时间约束。当前接受该残余，未引入异步解析线程。
- **跨源允许**（T3 裁定）：不转发任何头/凭据，逐跳完整复验；跨源重定向本身不是同源策略，
  若未来需要收紧，应作为独立策略面而不是在传输层临时加白名单。
