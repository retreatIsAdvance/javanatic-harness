## 1. URL 策略（`FetchUrlPolicyTest`，13）

命令：

```sh
$ ~/Documents/apache-maven-3.10.0/bin/mvn -B -pl web/fetch-http -am test \
    -Dtest=FetchUrlPolicyTest -Dsurefire.failIfNoSpecifiedTests=false
```

EXIT=0：

```text
Tests run: 13, Failures: 0, Errors: 0, Skipped: 0, Time elapsed: 0.022 s -- in io.javanatic.harness.web.fetch.http.FetchUrlPolicyTest
```

覆盖事实（方法名即断言）：

- `normalizesHostPortPathAndStripsFragment`：host 小写、缺省 443 不进 Host 头、fragment 不进请求目标。
- `convertsIdnToPunycodeAndEncodesNonAsciiPath`：`例え.jp` → `xn--r8jz45g.jp`；路径/查询按 UTF-8 百分号编码。
- `stripsTrailingDotAndNormalizesMissingPath`：尾点去除、空路径归一 `/`。
- `ipv6LiteralRequiresBracketsAndKeepsThemInHostHeader`：IPv6 仅方括号形态；Host 头带括号与端口。
- `literalIpv4IsMarkedAndCanonicalized`：`127.1` → `127.0.0.1`，`ipLiteral=true`（字面 IP 与 DNS 结果同闸的入口）。
- `preservesExistingPercentEncodingAndRejectsBrokenOne`：既有 `%20` 保留并大写；`%2` → `WEB_INVALID_URL`
  （消息为稳定的 `invalid percent-encoding in url`，不回显原 URL）。
- `rejectsNonHttpsAndMalformedShapes`：http/ftp/无 scheme、userinfo、host 百分号、非规范 IPv4
  `999.1.1.1`、端口 0/65536/非数字/空、未加括号 IPv6、空格、反斜杠、超 2048 全部 `WEB_INVALID_URL`。
- `relativeRedirectResolvesAgainstCurrentUrl` / `schemeRelativeAndCrossOriginRedirectsStayHttps`：
  相对、`..`、scheme-relative 与跨源 Location 均解析并保持 https。
- `redirectToPlainHttpIsBlocked`：https→http 降级 `WEB_REDIRECT_BLOCKED`。
- `badOrMissingLocationIsBlocked`：null/空白/坏方括号/`javascript:` 全部 `WEB_REDIRECT_BLOCKED`。
- `overlongRedirectTargetIsBlocked`：逐跳规范化后仍受 2048 上限约束。

## 3. 内容策略（`FetchContentTest`，9）

命令：

```sh
$ ~/Documents/apache-maven-3.10.0/bin/mvn -B -pl web/fetch-http -am test \
    -Dtest=FetchContentTest -Dsurefire.failIfNoSpecifiedTests=false
```

EXIT=0：

```text
Tests run: 9, Failures: 0, Errors: 0, Skipped: 0, Time elapsed: 0.007 s -- in io.javanatic.harness.web.fetch.http.FetchContentTest
```

覆盖事实：

- `text/html`、`application/xhtml+xml` → `Html`；其余 `text/*`、JSON、XML、`+json`、`+xml` → `Text`。
- 缺 `Content-Type`、白名单外（如 `application/octet-stream`）→ `WEB_UNSUPPORTED_CONTENT_TYPE`，消息含状态码。
- charset 缺省 UTF-8；`charset=utf-8` 带引号可解析；未知标签与 UTF-16/UTF-32 → `WEB_UNSUPPORTED_CONTENT_TYPE`。
- 非法字节序列 → U+FFFD（REPLACE），BOM 去除（内容事实，不猜测编码）。
- **T2 条件 ②**：`Content-Encoding: gzip`（含大小写变体）→ 显式 `WEB_UNSUPPORTED_CONTENT_TYPE`，
  消息说明 identity-only 且 no decoding attempted；`identity` 与缺失放行。
- 端到端同断言在 `PinnedHttpClientTest#gzipIsExplicitlyUnsupportedWithoutDecoding`（回环 HTTPS 真响应）。

## 4. 上限 / 超时 / 取消

（同一全量命令 EXIT=0；方法名与断言）

- `declaredTooLargeFailsBeforeBody`：`Content-Length: 9999999` 且 cap 1024 → `WEB_TOO_LARGE`，不读体。
- `streamedOverCapIsTruncatedNotAnError`：无 CL 的 2048 字节正文、cap 1024 → 结果 1024 字节、
  `truncated=true`（内容事实，不是错误）。
- `stalledResponseTimesOut`：夹具延迟 3s，客户端 `timeoutSeconds=1` → `WEB_TIMEOUT`；
  断言实际耗时 < 2500 ms（截止时间确实生效，而不是等到 3s）。
- `cancelWakesBlockedReadAsAbortedException`：阻塞读期间取消 → socket 被关闭、调用线程退出，
  异常类型是 `AbortedException`（非 `WebException`、非错误结果）。
- 协议侧 `chunkedOverCapStopsAndMarksTruncated` / `chunkedExactlyAtCapIsNotMarkedTruncated`
  见 `stop1-wire-chunked.txt`。

## 6. 已知残余（留给评审裁决，不在本停点静默处理）

- **DNS 解析不可被总截止时间硬中断**：总 30s 截止约束连接/握手/读写；系统 `getAllByName`
  若自身阻塞，`AbortSignal` 无法唤醒该调用。当前结构是“解析一次 + 钉地址”，解析时长由系统 resolver
  决定。是否升级为异步解析 + 超时放弃，交评审裁。
- **自定义 NAT64 前缀**：只封标准/本地前缀（R2 已登记 B17）；自定义 RFC 7050 前缀在地址形态上仍是
  `2000::/3` 全球单播，本闸无法仅凭地址识别其转换语义。
- **无代理/Cookie/Authenticator**：结构性不读取进程级默认值；本项目前没有“显式代理”需求，故无配置面。
