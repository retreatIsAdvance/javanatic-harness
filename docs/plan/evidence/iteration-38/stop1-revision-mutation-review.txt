Exceptions and interpretation
1. deadline-early 原 audit 的 BEHAVIOR_RED=False、PASS=False 如实保留。
   旧分类器只认 failure，实际 Surefire 把生产 RpcException 记作 error；不能据此将它排除为非行为红，也不能泛化为任意 error 都算杀死。此例有明确变异 >=-1、期前 1ns、approval expired 的调用栈、相同选择器复绿与 SHA 恢复，和既存 adjudication 一致，因此本次裁定捕获。其余 13 项 audit 均为 BEHAVIOR_RED=True、PASS=True；14 项均 BYTE_RESTORED=True。

2. b37-writes 红侧的 6 failures + 1 error 全部解释为同一条件反转：
   - postWithoutContentTypeYields415、postFormEncodedYields415、postTextPlainYields415：期望 415，实际 200。
   - allWriteMethodsRejectInvalidContentTypeBeforeDispatch：[session/start] 期望 415，实际 200。
   - e2eRoundTripsFiveMethodsOverHttpWithJsonContentType：正常 JSON 期望 200，实际 415。
   - writeMethodPostWithoutOriginReachesSeam：[session/start] 正常 JSON 期望 200，实际 415。
   - concurrentTailRequestsShareNoState：ExecutionException 包装 JsonParseException；tailResult 的 readTree 收到以 'content' 开头而非 JSON 的拒绝响应，解析在 line 1 column 8 失败（日志:8-34，RpcHttpServerTest:254/506/244）。这与正常 JSON 被反转闸错拒 415 的结果相符，不是新的并发共享状态或非突变 JSON 缺陷。还原后整个类 21/0/0/0、EXIT=0。

3. 不把日志严重级别或 WARNING 当测试失败。
   b36-events 的 missing SSE codec: test/chunk、SSE source returned null 诊断在 red.log:5-27 与 green.log:5-27 都存在；绿结果仍为 21/0/0/0。红侧实际唯一 failure 是围栏的 403→200，不将这些诊断另算环境红或新缺陷。各红日志的 Unsafe 弃用 WARNING、b37 的 HEAD content-length 警告也不是本次红因。

4. 证明范围限于这 14 个具体突变。
   每项都已有非零运行测试数、可解释的目标行为 failure/error 和还原后非零测试数的绿结果；所读红日志均进入 Surefire 测试阶段并给出相应栈，无一以编译/门禁/依赖解析/启动环境失败替代目标行为红。单个测试在首个断言失败后可能未执行后续断言：b37 写面失败标签只显示 session/start，b36 日志只定位一处围栏失败，codec 红只显示首个缺载荷断言；不据方法名称夸称所有分支、所有 chunk 变体或每个写方法均分别杀死突变，也不据本核验宣称当前压力测试/全量门禁通过。
