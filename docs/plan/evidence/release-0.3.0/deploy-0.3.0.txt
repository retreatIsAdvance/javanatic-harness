环境：Maven 3.10.0（~/Documents/apache-maven-3.10.0）、JDK 25、GnuPG 2.5.21

一、尝试 1（central-publishing-maven-plugin 0.11.0）
- 失败点：根 POM 签名，maven-gpg-plugin 3.2.8 exit 2
  gpg: 签名时失败： 缺少 pinentry / gpg: signing failed: 缺少 pinentry
- 处置：gpgconf --reload gpg-agent 后重试

二、尝试 2（0.11.0）
- 构建、签名、bundle 上传均成功；deploymentId 236aeb20-ca9b-4443-90ac-50aba1364809
- Central 校验失败，BUILD FAILURE（central-publishing:0.11.0:publish @ harness-dist-jh）
  Bundle has content that does NOT have a .pom file: <59 个坐标>
- 本地 bundle 复核（target/central-publishing/central-bundle.zip，1518 条目）：
  59 个 .pom 齐全，194 个 .asc 齐全，但混入了
  - 59 × maven-metadata-local.xml（artifact 层，无 .pom 的目录内容）
  - 354 × _remote.repositories[.md5/.sha1/.sha256/.sha512]（version 层）
- 根因：Maven 3.10 下 0.11.0 在打包前不剔除 staging 元数据；Central 按目录校验，
  artifact 层只有 maven-metadata-local.xml、没有 .pom → 全部 59 坐标被拒。
  官方修复：central-publishing-maven-plugin 0.12.0（2026-10-13 Release Notes：
  Fixed deployments being rejected by Central when built with Apache Maven 3.10.0）。

三、修复与尝试 3
- 根 POM pluginManagement：central-publishing-maven-plugin 0.11.0 → 0.12.0（附注释）
- 清理 target/central-staging、target/central-publishing 后重跑
- 再次触发「缺少 pinentry」；relaunch 前置：gpgconf --kill gpg-agent &&
  gpgconf --launch gpg-agent，随后 --batch 探测签名 SIGN_EXIT=0
