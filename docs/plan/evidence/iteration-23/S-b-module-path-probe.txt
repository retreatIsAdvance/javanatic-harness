# ---- 3) 负例：插件目录（无 module-info.class 的散装 classes）放 module-path 不被当作模块 ----

# （原因：--module-path 只接受 jar/显式模块；散装目录不是自动模块 → 需打成 jar。同类处置见 §6）
$ "${JAVA_HOME}/bin/java" --module-path "<H+T>/tmp/embedprobe/sample-classes" --add-modules ALL-MODULE-PATH -cp out probe.Probe <profile>

# ---- 4) 正例：示例打成 jar（自动模块）→ 服务提供者由 META-INF/services 派生，boot 成功 ----
$ "${JAVA_HOME}/bin/jar" --create --file sample.jar -C sample-classes .
$ "${JAVA_HOME}/bin/jar" --describe-module --file sample.jar
找不到模块描述符。已派生自动模块。
sample automatic
requires java.base mandated
provides io.javanatic.harness.kernel.plugin.Plugin with io.github.retreatisadvance.sample.consumer.WordCountPlugin
$ "${JAVA_HOME}/bin/java" --module-path "<H+T>/tmp/embedprobe/sample.jar" --add-modules ALL-MODULE-PATH -cp out probe.Probe <示例 profile>
module-path probe ok: io.javanatic.harness.kernel.scope.ScopeImpl
# 结论：module-path 路线端到端可用（编译 + 组合 + 装配），前提 = 模块 jar 全量 + 第三方闭包 + 提供者模块被解析。
# 探针用 --add-modules ALL-MODULE-PATH 图省事；生产写法是 --add-modules <你的模块名>。
