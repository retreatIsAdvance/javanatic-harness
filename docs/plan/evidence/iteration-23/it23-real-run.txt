## 走查发现的文档缺陷（1 处）→ 已修（迭代内，S-c）

**§5 的 `(disabled: <expr>)` 注记与示例代码自相矛盾**：示例按 `AppBoot.dump(enabled)`（`enabled =
resolve(composed)`，已滤掉禁用行）调用，而紧随的说明写「禁用行附 `(disabled: <expr>)`」——按示例照做
**永远看不到**该注记。

实证（`DumpComposed.java`：dump **未 resolve** 的 `compose(...)` 结果）：

```
$ java -cp "target/classes:$(cat cp.txt)" dev.walkthrough.DumpComposed profile/fresh.yml

approval-ask  (disabled: true)
approval-deny  (disabled: true)
shell-docker  (disabled: true)
compaction  (disabled: true)
（共 5 行带注记）
$ grep -c disabled <dump(resolve) 输出>   → 0
```

修复（`docs/embedding.md §5`）：改为「`dump(enabled)` 输出一行一插件（…凭据键脱敏）；`(disabled: <expr>)`
注记只在 dump **未 resolve** 的 `compose(...)` 结果时出现——`resolve` 后的列表已滤掉禁用行」。
