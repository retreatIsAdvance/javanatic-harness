1. r1 全绿中 M6 红不达标：恒 null 突变体删掉 Files 引用后，未使用导入被 spotless:check 拦截，

   脚本回退 PATH 上的 mvn → FileNotFoundError；崩溃时 M1 突变已注入尚未还原，
   工作树 JdtlsProvider.java 被留成 M1 突变态（MD5 c2f86456…≠基线）。r2 因此 M1 old 串失配、
   M7 green 受污染失败。
3. r2 的 M6 红改法一（摘除导入）仍不达标：读面摘净后外层 catch(IOException) 成为不可达
   检查型异常 → 编译错误（「在相应的 try 语句主体中不能抛出异常错误java.io.IOException」），
   仍无测试失败标记。
4. 最终修法（r3 达标）：M6 突变体保留 exists+readString 读面（Files 导入仍被使用、
   IOException 可达面仍存在），内容一律弃用恒返回 null——上界确定性红语义不变；
   隔离预检（/tmp/it29-m6-isolated-red.log）先行验证：注入后单测 10.31s
   "Expecting actual not to be null"（JdtlsProviderTest.java:419）真实红，还原后 MD5 一致。
5. JdtlsProvider.java 崩溃残留用 /tmp 快照还原（diff 恰等于 M1 两处突变），
