S-0 形状追查证据：WRITE_RESTRICTED → 低完整性（真 Windows 实跑，轮次 8–12）
======================================================================

来源：it25 S-0 首跑（探针套件 S-0-windows-probe.java，输出 S-0-windows-probe.txt）
     落点 failures=1——grant-write 腿（per-workspace SID 授权后应可写）未通过，且三腿
     共性是受限子进程当场 0xC0000142。按裁决增强 4「任一符号/结构布局不可用都改变实现
     形状」，本档记录改用一次性诊断（S-0-windows-acl-shape.java，C:\jh\mx 内真跑）
     逐轮追查的原始输出与最终形状裁定。

环境：UTM / Windows 11 25H2 ARM64 虚拟机（计算机名 WIN-088T9S8V0LT）；用户 j'h
     （本机管理员、EnableLUA=0）；JDK 25.0.4.1（C:\jh\jdk）；诊断工作目录 C:\jh\mx；
     控制台 GBK（本档全部输出已转 UTF-8）；pwsh 不存在（PS 5.1.26100.7920）。

运行方式（utmctl）：file push 投递 .java/.cmd → schtasks（/ru "j'h" /it）在交互会话内
     以 j'h 身份运行 round*.cmd（cmd 重定向落盘）→ file pull 回读诊断文件。exec 的
     stdout 不可靠（陈旧输出先例在案），一律以文件回读为准。

一、结论（S-a 直接采用）
----------------------------------------------------------------------

1) **WRITE_RESTRICTED 形状作废**。令牌构造与 ACL 授权全部成功（CreateRestrictedToken
   ok=true、SetEntriesInAclW/SetNamedSecurityInfoW ok=true），子进程却一律以
   -1073741502 = 0xC0000142 STATUS_DLL_INIT_FAILED 死在启动初始化（轮次 8/9/10/11 四轮
   复现）。决定性对照：
   - 同样令牌 + 不限制控制台（flags=0 继承 console）→ exit=0（轮次 9 A2 腿）；
   - CREATE_NO_WINDOW 下唯一能启动的受限 SID 是 **Administrators**（S-1-5-32-544）；
     Everyone / INTERACTIVE / 用户 SID / 登录 SID / 随机 S-1-5-x 全部 0xC0000142
     （轮次 9/10 全谱，ASCII 输出见 §2）；
   - 给随机 SID 逐个授权目标目录 / HKCU\Console / HKCU 根 / WinSta0 / WinSta0\Default，
     甚至自建 window station + desktop 并用 lpDesktop 指定，**均不能修复**（轮次 9/10）
     ⇒ 死因不是这些对象的 DACL；应用事件日志无 WER/Application-Error 记录（轮次 10），
     行为矩阵是唯一取证手段；
   - 受限 SID 列表取 {随机 SID, Administrators} 后子进程可启动，但写限制**形同虚设**：
     未授权目录照写（轮次 11 P4 腿 wrote=true）——默认 DACL 普遍授予 Administrators，
     受限检查被其满足 ⇒ 该形状无安全价值。

2) **形状改为低完整性（Low IL）**，轮次 11 L 腿 + 轮次 12 复现腿全数通过：
   - 令牌：CreateRestrictedToken(flags=DISABLE_MAX_PRIVILEGE, 0 个受限 SID，即无写限制位)
     + SetTokenInformation(TokenIntegrityLevel=25, {S-1-16-4096, attrs=SE_GROUP_INTEGRITY
     (0x20)}, 16B)；CREATE_NO_WINDOW 下子进程启动正常（exit=0，无 0xC0000142）；
   - 写入面由强制完整性策略（MAC）管控：写 Low 标签目录**成功**、写中标签（含 DACL 已
     授权的）目录**被拒**（exit=1、文件不存在）；读取不受限（低完整性默认无 read-up）；
   - **形状简化**：05 §6 既定设计的「per-workspace SID 常设授予」与「per-session 随机
     SID/临时目录」两个机制整体退役——令牌构造不再需要 AllocateAndInitializeSid（Low IL
     SID 是固定常量 S-1-16-4096），工作区可写性改由标签面表达。

3) **打标可纯 FFM**（轮次 12，无需 icacls）：
   ConvertStringSecurityDescriptorToSecurityDescriptorW("S:(ML;OICI;NW;;;LW)", rev=1) →
   取回自相对 SD（control=0x8010、SACL 偏移自 offset 12 读出）→
   SetNamedSecurityInfoW(path, SE_FILE_OBJECT, LABEL_SECURITY_INFORMATION=0x10,
   SACL=该指针) → ok=true。SACL_SECURITY_INFORMATION=0x4 位在管理员令牌下亦 ok（本机
   EnableLUA=0 全管理员）；采用 0x10（LABEL 位的存在意义即免 SeSecurityPrivilege，
   普通用户会话下可用）。icacls 等价物实测于轮次 11（`icacls lowdir /setintegritylevel
   (OI)(CI)L` 产出 `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`，随轮输出见 §2）。

4) **递归打标是硬性义务**：标签不向已存在子对象回溯传播（轮次 12 复现：打在目录上的
   (OI)(CI) 只影响此后新建对象——打标前已存在的 pre.txt 保持中标签，Low 子进程写它
   被拒、文件长度 13B 未变；同一目录里新建文件则可写）。会话可写区域 = 工作区树需
   逐对象打 Low（目录 + 已存在的文件）；新对象由 (OI)(CI) 继承覆盖。

5) **两洞重述**（替代 05 §6 既定设计的旧两洞，S-a 的 Ready.detail 须携带新版）：
   - 旧洞「Everyone-可写外部对象仍可写」不再成立（MAC 不理会 DACL——DACL 已授权的
     中标签目录照样拒写，轮次 11 L4 实证）；**新洞 1**：可写面 = 主机上一切 Low 标签
     对象（例：同机其它低完整性沙箱的目录/文件），不再限于工作区树——边界外对象若为
     Low 标签即可写、且其内容（低完整性对象对低完整性主体）可读；
   - 旧洞「NTFS 硬链接别名越界」归**待实测**（推论：硬链接与目标同属一个文件对象、
     同标签 ⇒ 不构成越界；轮次无直证，S-a 探针可顺手验证）；
   - 打标有**主机足迹**：Low 标签打在用户工作区对象上是持久元数据（可还原为 M/中标签），
     会话崩溃/强杀时的还原义务与打标成本（大树递归）是 S-a 的设计决策项；
   - 提示（推论，未实测）：子进程 TEMP/TMP 宜指向 Low 目录，否则工具链写临时文件即被拒。

6) 备选与不可达路径：CreateProcessWithTokenW 腿在首跑里真启动了子进程（pid=788）但
   退出码不可判定（探针 `waitExit` 回落 -1：WAIT 超时或 GetExitCodeProcess 未成功）——
   备选路径不在采纳形状内，未再追查；`CreateFile("\\.\ConDrv")` errno=2
   (ERROR_FILE_NOT_FOUND)，控制台对象 DACL 理论不可验证（形状改 Low 后已于事无补）。

四、FFM / Win32 事实订正清单（累计，S-a 绑定层直接照做）
----------------------------------------------------------------------

  1. advapi32 不导出 LocalFree（首跑 MISSING）——kernel32 绑定。
  2. Windows 捕获状态段 = 12 字节（Linker.Option.captureStateLayout()），不可按 4 字节分配。
  3. AllocateAndInitializeSid 的 dwSubAuthority0..7 = 8 个 DWORD 形参（原型 11 参）。
  4. 语句上下文 invokeExact 会被编成 (…)void 描述符 → 返回值必须有承接（close/freeLocal
     等包装的由来；同一坑在自定义绑定里重复出现）。
  5. SID_AND_ATTRIBUTES.Attributes：受限 SID 列表须为 0（SE_GROUP_ENABLED 报 87）；
     低完整性标签须为 SE_GROUP_INTEGRITY(0x20)。
  6. TOKEN_GROUPS 数组起点 = count DWORD 之后的偏移 8（4 字节对齐填充），不是 4。
  7. OpenWindowStationW / OpenDesktopW **返回**句柄（无出参）；按出参形调用 ⇒
     WrongMethodTypeException。
  8. GetSecurityInfo / SetSecurityInfo 参数序：
     (err, handle, objectType, securityInfo, owner, group, dacl, sacl, sd/pSD)。
  9. WRITE_RESTRICTED + CREATE_NO_WINDOW 的子进程 0xC0000142：令牌/授权全 OK 也死；
     唯一可启动的受限 SID 是 Administrators，而其一旦入列写限制即形同虚设（P4 直证）
     ⇒ 写限制形状弃用，改低完整性。
 10. SetTokenInformation(TokenIntegrityLevel=25, {SID_AND_ATTRIBUTES}) 形参 = (err, token,
     class, ptr, 16)；readback GetTokenInformation 在本探针内读回失败（ok=false，未深究，
     行为腿已证生效）——S-a 若要读回需另查缓冲/类号口径。
 11. ConvertStringSecurityDescriptorToSecurityDescriptorW(rev=1) 产出**自相对** SD
     （control=0x8010）：SACL 指针 = 基址 + offset(12) 处的 DWORD；绝对布局才是 offset 24
     的 8 字节指针——两形都要处理。
 12. `\\.\ConDrv` 经 CreateFileW 不可打开（errno=2 ERROR_FILE_NOT_FOUND）——控制台对象
     DACL 面不可经此验证（形状改定后不再需要）。
