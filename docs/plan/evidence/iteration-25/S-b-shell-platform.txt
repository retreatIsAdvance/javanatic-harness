== 4. 真执行与方言（leg1 exec / leg2 exitcode / leg3 dialect） ==

leg1（真执行：stdout/stderr/退出码/时长/行尾）：
  [exec] exit=3 expect=3
  [exec] stdout=hello\r\n
  [exec] stderr=oops\r\n
  [exec] durationMs=572 truncated=false denied=false
  [exec] lineSeparator=\r\n
  [leg1] exit=0

leg2（退出码方言三题）：
  [exitcode] explicit-exit exit=7 expect=7                 ← `exit 7` 原样上浮
  [exitcode] native-no-mapping exit=1 (… native=9)         ← `cmd /d /c exit 9`：原生命令非零码
                                                             不回传为 pwsh 进程退出码（观测 exit=1）
  [exitcode] native-mapped exit=9 expect=9                 ← if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE } 显式上浮
  [leg2] exit=0

leg3（引号 / 变量 / && / 重定向字节）：
  [dialect] env-access stdout=bare=[]\r\nenv=[passed]\r\n
      ← 同一命令串 `"bare=[$JH_TEST_VAR] env=[$env:JH_TEST_VAR]"`：POSIX 的 $VAR 不展开（裸 []），
        pwsh 须 $env:VAR（[passed]；环境经 ShellRequest env 传入）
  [dialect] quoting stdout=single=$env:JH_TEST_VAR\r\ndoubled=it's\r\ninterp=\r\n
      ← 单引号字面（$env: 不展开）；'' 转义出 it's；双引号可插值（此腿未置该变量故空）
  [dialect] andAnd exit=0 stdout=a\r\nb\r\n               ← pwsh 7 原生支持 &&
  [dialect] redirect exit=0 bytes=780d0a size=3           ← 'x' > file：UTF-8（无 BOM）内容 + CRLF 行尾
  [leg3] exit=0

判读：同一契约面（ShellResult：exitCode/stdout/stderr/duration/lineSeparator）在两方言下
语义不同但形状统一；方言差异事实登记在此，契约断言在分区后的 JUnit 面（§9）。

== 11. 首跑红现场与产品代码修正（唯一的 S-b 主源码改动） ==

现场（第二真跑 16:34，pwsh 已装且 where 命中，leg0b 仍 fail-loud）：
  [install] where-after-install exit=0（C:\jh\pwsh\pwsh.exe）
  [leg0b] ShellUnavailableException=… pwsh (PowerShell 7) not found on PATH …
  [leg0b] verdict=FAIL-LOUD pwsh-absent        ← 缺陷现场：pwsh 在场却探不到
同轮探针（16:36，同 VM）：
  [probe] env[Path]=<C:\WINDOWS\system32;…;C:\Users\j'h\AppData\Local\Microsoft\WindowsApps>
  [probe] get(PATH)=<…>  /  get(Path)=<…>        ← System.getenv(name) 访问器大小写不敏感
  [probe] isRegularFile(C:\jh\pwsh\pwsh.exe)=true
  [probe] host-argv EX=…ShellUnavailableException…

根因：`System.getenv()` 的 Map 视图按**精确键名**查找（只有 `System.getenv(name)` 访问器
大小写不敏感）。Windows 系统变量惯名为 `Path`；旧代码 `System.getenv().getOrDefault("PATH","")`
在 Windows 上恒为空表 ⇒ pwsh 永不入候选 ⇒ 首条命令必 fail-loud（机制其余部分无恙——本机
darwin 上 PATH 恰为精确大写，故单测全绿，缺陷只由真 Windows 首跑暴露）。

修法（主源码唯一改动）：`ShellPlatform.pathEntries()` 增显式环境映射参数版
（`pathEntries(Map<String,String>)`，键名 equalsIgnoreCase 匹配），`host()` 经 `System.getenv()`
传入；新增回归用例 `pathEntriesIsCaseInsensitiveAcrossWindowsAndPosixKeyShapes`（Path/PATH/
无关键三形态）。突变 M-Sb6 证明该用例承载真事实（§10）。收官轮 16:45 leg0b READY（§3）。
