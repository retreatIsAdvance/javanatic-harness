== 4. 打标成本（leg8，:120-128） ==

方法：同一台 VM、同一助手，分别对 2000 文件树与空树跑 workspace-write 会话
（`cmd.exe /d /c exit 0`），PowerShell Stopwatch 包住整个 java.exe 启动；两次读数：

  收官轮：leg8 big2000-ms=942 / empty-ms=463（begin 14:53:45.09 → end 14:53:48.46）
  首跑：  leg8 big2000-ms=932 / empty-ms=483

判读：两值都含 JVM 启动等固定开销；差值 ≈ 460–479 ms / 2000 文件 ⇒ 打标边际成本 ≈ 0.23–0.24
ms/文件（线性外推，仅到 2000 深度有限）。结论行同轮内两次读数差 <5%，量级可信。

== 5. 两洞实测（leg9 洞 1 / leg10 洞 2） ==

洞 1（leg9，:130-144）：可写面是「主机上一切 Low 对象」，不限于策略根。
  icacls C:\jh\mx\a5foreign /setintegritylevel "(OI)(CI)L" → exit=0，标签实证
  `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`；
  随后一次 **read-only** 会话写该目录：
  [leg9] read-only-to-foreign-low exit=0
  [leg9] hole2.txt exists=true WRITABLE-SURFACE-IS-GLOBAL-LOW
  判读：MAC 只问对象标签、不问策略词——任何进程把工作区外对象标成 Low（icacls 即可），该对象
  就进可写面。这条坐实了 Ready.detail 的「writable surface = every low-labeled object on this
  host」不是修辞。

洞 2（leg10，:146-159）：打标会顺硬链接泄漏到工作区外的目标对象。
  mklink /h %WS%\hl-alias.txt %OUT%\hl-target.txt → exit=0（目标在工作区外，内容 src-medium）；
  随后一次 workspace-write 会话（打标 pass 会走遍树内对象）：
  [leg10] write-via-alias exit=0
  [leg10] hl-target.txt content outside the workspace: src-medium + hacked
  [leg10] hl-target.txt label after labeling pass: … Mandatory Label\Low Mandatory Level:(NW)
  判读：硬链接不带重解析属性（reparse point）⇒ 打标 pass 的 reparse 护栏漏掉它，Low 标签落到
  工作区外的目标对象上——目标由此进入可写面（追加成功），且标签是持久元数据。**推翻 S-0 的
  推论**「硬链接与目标同对象同标签 ⇒ 不构成越界」（该推论假设标签已存在；实际是打标 pass
  自己把标签写到了外部目标上）。0.2 不做检测（需 GetFileInformationByHandle 查 link count），
  如实进 Ready.detail + 05 §6。

== 7. D4 /dev/null：测量项落地 + 本机边界（事实待真 landlock 宿主） ==

D4 内容（it25 裁决记录）：「`/dev/null` 顺手实测出选项（runner 真 landlock 宿主 ABI v7，一条
e2e 出事实再裁，不带预判）」。

`landlockDevNullWriteIsMeasuredForAdjudication`（正对照工作区写成功 + `echo probe > /dev/null`
结局二选一：exit 0 或 EACCES 方言拒绝，两分支都过并把实测分支出 stdout——console 与 surefire
XML system-out 双落点，供真 landlock 宿主运行时取证）。

本机边界（两条事实，均为今日实测）：
- 本机容器（docker 24.0.6，内核 6.4.16-linuxkit，未编译 CONFIG_SECURITY_LANDLOCK）：
  $ java … LandlockExecMain --probe
  landlock: unavailable — landlock syscalls not present (errno ENOSYS)
  PROBE-EXIT=10
- 同容器内经助手做「D4 测量」的尝试（本档命令即真实测量形态）：
  $ java … LandlockExecMain --mode workspace-write --root /tmp/d4ws -- sh -c 'echo probe > /dev/null'
  landlock: unavailable — landlock syscalls not present (errno ENOSYS)
  MEASURE-EXIT=10                      ← 助手 fail-closed：命令根本没跑，问题在本机不可判定
- 非受限对照（同容器）：`sh -c 'echo probe > /dev/null'` → UNCONFINED-EXIT=0（宿主本可写）

⇒ 本机（darwin 无 landlock；本机容器内核无 landlock）**无法取得该事实**——事实唯真 landlock
宿主可出：首个可及场所 = CI ubuntu job（runner 内核 landlock ABI v7，it24 第三轮已证）。
故 D4 在本停点交付「测量项 + 边界 + 选项」，事实随 S-c 首轮 CI 回填后再裁。选项：
  A. 文档化差异（维持 05 §6 已知残余）——seatbelt 显式放行 `(literal "/dev/null")`、bwrap 新
     devtmpfs、landlock 腿拒绝；
  B. 设备节点例外——在 landlock ruleset 里为 `/dev/null` 增显式规则（上游 `landlock_add_rule`
     的 `parent_fd` 语义可指向单文件；此为文档级事实，若选 B 在 S-c 对照内核文档复核）。
S-c 挂钩（防事实静默丢失）：把该用例名并入 CI「landlock e2e ran for real」断言集（步骤 8 的
want 集合），并从日志/XML 收割 `[D4] landlock leg /dev/null write: …` 行。
