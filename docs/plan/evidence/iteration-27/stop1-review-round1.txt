## 1. F1 修复面（取消链轮询路径收口）

- `JsonRpcPeer.request` 等待循环：`try { signal.checkAbort(); } catch (AbortedException e) {
  cancelPending(id, slot, e); throw e; }`——轮询型 signal（不实现 onCancel）的直接抛出
  会绕过收口（槽泄漏 + 不发 `notifications/cancelled` + 撤销记忆漏记）；onCancel 型已由
  注册回调收口，`cancelPending` 幂等去重。
- 钉死测试件：`Fixtures.PollOnlySignal`（不实现 onCancel，默认空操作）；夹具
  `--record-cancel-to P`（收到 `notifications/cancelled` 时把 requestId 写入 P）；
  新用例 `McpStdioCallTest#pollOnlyCancelNotifiesServerAndDropsLateResponse`——中途取消后断言：
  AbortedException 上抛 + 夹具记录文件出现（通知已发）+ 晚到响应静默丢弃（JUL 捕获
  peer 日志树，无 unmatched WARN）+ 取消后连接保持可用。
