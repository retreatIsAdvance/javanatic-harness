## 二、导出类型签名（破坏性变更扫描，2026-11-24 方向订正）

**先给方向（旧稿写反，已订正）**：`RpcHttpServer.java` 的 `synchronized` 在 v0.5.0 = **0**、
0.6.0 树 = **4**（`:98 start` / `:111 address` 两个方法修饰符 + `:219` / `:253` 两个内部
同步块）——it38 `27b2d88` **新增**的并发加固，**零删除**。模块面同向：`workbench/rpc`
主源 0 → 19（ApprovalRelay 8 / RpcHttpServer 4 / SseBuffer 4 / SseConnection 3），
测试 0 → 6。

公开/保护签名面：`git diff -U1 v0.5.0..HEAD -- .../RpcHttpServer.java` 的两组变化均为
`- public void start(int)` → `+ public synchronized void start(int)`、
`- public InetSocketAddress address()` → `+ public synchronized InetSocketAddress address()`：
**成员保留、参数不变、仅新增修饰符**；无 public/protected 成员删除。旧稿把 `+` 侧的
`synchronized` 写到了删除侧（`-` 行是旧签名，不带修饰符），方向倒置，见 §九。

**为什么该同步是对的（delta 说明，不只记 delta）**：it38 SSE 写面引入三类并发竞态，
锁面就是它们的治理边界：

1. `serveEvents` 迟到 open vs `close()`：外部 `source.open` 不可中断，返回时 server 可能
   已关；`synchronized (this)` 内做 `accepted = !closed` 的登记/拒绝判定，锁外撤销连接，
   **绝不发出 SSE 200**。钉死测试 `openReturningAfterServerCloseCannotLeakRegistration`。
2. `close()` 幂等快照 vs 外部回调：锁内取 `connections/server/executor` 快照并置 `closed`，
   锁外 `stop` / 逐连接 `close` / `shutdownNow`——回调里再调 `address()` 不会自锁。
   钉死测试 `closeCallbacksRunOutsideGlobalLockAndOneFailureCannotLeakOtherConnections`
   （回调内用另一虚拟线程探测 `address()`，持锁即超时失败）。
3. `start()` 的 check-then-act（`closed || server != null` → 建 server / executor / start）
   与 `close()` 同锁，避免「关后启动」与双重启动泄漏已绑定 socket；`address()` 同锁保证
   server 引用的发布与读取原子。内部块 `:219` / `:253` 位于 private 方法体，**不在导出面**，
   此处仅作原因登记。

**旧稿倒置的根源（工具 / 转写）**：diff 本身方向正确（`-` 旧、`+` 新）；审计命令只抽了
`git diff | grep '^-'` 的删除侧，随后 packet §三 把 `+` 侧的 `synchronized` 转写到了删除
侧——**单方向抽取 + 人工转写**，不是 diff 箭头错。其余「相同」结论已按双向断言重做（§九）。

无参数列表变更（`WorkbenchRpc` / `RpcHttpServer` 新增构造重载，既有构造逐字保留；
`boot.AppBoot` 新增 `bootReported(BootOptions, ApprovalPrompt)` 重载）。`BootOptions`
无 diff。sealed permits：`SessionEvent` 文件 v0.5.0→HEAD **零改动**。record 组件：既有
record 零改动；新增 record 均在新增类内（`ApprovalRelay.Pending` / `SseFrame` /
`SseRequest` / headless 内 `ServeStartup` 等），属 0.6 新面纯增量。

## 九、方向显式复核（2026-11-24，订正后重跑）

对旧稿的「逐字相同」结论做**双向集合差**（`comm -23` = 仅 v0.5.0 有；`comm -13` = 仅
HEAD 有），两侧同时为零才算相同：

| 面 | v0.5.0 | HEAD | 仅 v0.5.0 | 仅 HEAD |
|---|---|---|---|---|
| exports 唯一包 | 60 | 60 | **0** | **0** |
| 非 harness `<artifactId>` | 24 | 24 | **0** | **0** |
| base bundle 行 | 41 | 41 | **0** | **0** |
| `SessionEvent.java` | — | — | 逐字节相同（`diff -q` 空） | 同左 |
| `synchronized`（RpcHttpServer.java） | 0 | 4 | **0（零删除）** | **4（新增）** |

复跑命令（仓根）：

```sh
# exports 双向差
git grep -h -E '^[[:space:]]*exports[[:space:]]+[a-zA-Z0-9_.]+' v0.5.0 -- '*module-info.java' \
  | sed -E 's/^[[:space:]]*exports[[:space:]]+//; s/[;[:space:]].*$//' | sort -u > /tmp/e050
git grep -h -E '^[[:space:]]*exports[[:space:]]+[a-zA-Z0-9_.]+' HEAD -- '*module-info.java' \
  | sed -E 's/^[[:space:]]*exports[[:space:]]+//; s/[;[:space:]].*$//' | sort -u > /tmp/e060
comm -23 /tmp/e050 /tmp/e060 | wc -l; comm -13 /tmp/e050 /tmp/e060 | wc -l   # 0 / 0
# 非 harness 依赖双向差（每次换 ref 重跑，过滤 harness-* 与 consumer-sample）
git grep -h -E '<artifactId>[^<]+</artifactId>' v0.5.0 -- '*pom.xml' \
  | sed -E 's/.*<artifactId>([^<]+)<\/artifactId>.*/\1/' \
  | grep -vE '^harness-' | grep -vx 'consumer-sample' | sort -u > /tmp/d050
# ...同法生成 /tmp/dHEAD 后：comm -23 → 0，comm -13 → 0
# bundle 行双向差
git show v0.5.0:bundle/base/src/main/resources/META-INF/harness/bundle.yml \
  | grep -E '^[[:space:]]*-[[:space:]]' | sed -E 's/^[[:space:]]+//' | sort > /tmp/b050
# ...HEAD 同法生成 /tmp/bHEAD 后：各 41 行，comm 两侧均 0
# synchronized 方向
git grep -o synchronized v0.5.0 -- 'workbench/rpc/src/main/java/**/RpcHttpServer.java' | wc -l  # 0
git grep -o synchronized HEAD -- 'workbench/rpc/src/main/java/**/RpcHttpServer.java' | wc -l    # 4
```

结论：其余「相同」结论在双向口径下成立；唯一例外 = `synchronized` **新增**，方向已在 §二
订正。pits 候选：发布审计的 delta 方向要机器判定 + 双向断言（「A 有 B 无」与「B 有 A 无」
分开报），人工转写方向是最容易静默翻车的一格。
