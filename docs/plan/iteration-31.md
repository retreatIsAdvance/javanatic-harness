0.4 后半（[路线 §0.4.2](../design/README.md) 六要素：父子所有权 / 权限继承不扩权 / 有界并发·调用深度·总预算 / 问答统一路由 / 结果终局 / 父取消子收敛）。基线：it30 已关账（`f5b1eb8`），master `3fa585f`。前置侦察：[dsh 委派面侦察](evidence/iteration-31/dsh-delegation-recon.md)（已过评审）——「立即返名 + 异步完成通知 ≅ job/snapshot」为 it30 复用的最强证据；dsh「opportunistically 继承」是含糊点不是先例。

## 四确认

- **内容**：in-JVM 委派最小闭环——`delegation` 组三角色（草案裁定①布局）：Definition（DelegationService：spawn 子代 = 新 Agent 挂 durable 子会话、返回子代名；发现/清单；终局结算）+ in-JVM Provider + 工具面（delegate 启动 + 子代清单/中断）。**双闸**：`maxDepth` 缺省 1（0 = 禁）+ `maxActive` 缺省 8（预留-放行-还槽准入，降额不杀驻留——it30 容量语义复用）。**事件**：委派终局走 job/snapshot 同族全量快照 fold（ignorable、不进 prompt）。**硬约束三条**：权限继承 = **spawn 时点显式快照、子只窄不宽、不追踪父后续变更**（继承面四项：工具面 / 沙箱策略 / 审批档 / 预算——执法点在子 scope 装配期，草案裁定②）；`ask_user` 路由 = **子的问题汇入父会话单一人闸**（it22 exit-5 子代版：子带「需父输入」终局、父转述——**禁嵌套审批队列**）；子 token **计入树总预算**（LoopGuard 面，路线第三项）。
- **目标**：验收两轴——①要素轴：六要素场景各取证（父子取消级联 / 权限收窄反例 / 深度与容量双闸 / 问答路由 / 结果终局恰一次）；②**收益轴（双臂真 key）**：固定任务集两族（可并行分解族 + 内在串行族）× 单 Agent 臂 vs 委派臂，同任务文本同工具面；量纲三条 + 底线一条——**总 token / 墙钟 / 父上下文占用（完成时）** + 任务成功率持平（委派臂不低于单臂）；任务集 ≤ 10 任务 × 两臂（草案裁定③任务集成员与「委派赢了」的判读阈值）。
- **为什么**：0.4 序的兑现（后台任务 = 执行地基已关账，委派 = 组合收益证明）；it30 机器复用（取消收敛 / 终局恰一次 / 容量准入 / 异步事件口径——侦察 §2 直引）；JH 显式快照继承优于 dsh 的含糊继承（kernel 子 scope 天然支持，侦察 §3.2）。
- **不做**：越进程后端（ACP / Codex / Claude / SDK——00 §6 非目标）；team 共享任务板（experimental，六要素不需要）；workflow / goal / schedule / PTC（后续裁决）；fork 历史种子子代（草案裁定④：v1 不含或纳入）；命名 provider 注册表抽象（v1 单 provider，seam 留位）。
