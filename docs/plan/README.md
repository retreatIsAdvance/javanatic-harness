# 迭代验收清单（plan/）

每迭代一个 `iteration-N.md`：四确认（内容 / 目标 / 为什么 / 不做）+ 设计增量 + 锚点 + 审查停点 + 验收清单（勾选 + 证据）+ 修正 / 设计偏离记录。
**落盘是开工的前置条件**；验收项全部勾选且证据在案（实际执行的命令与结果）才进入下一迭代——对应 AGENTS.md「迭代仪式」「审查停点」与「证据匹配改动面」。

## 生命周期

草稿（四确认达成时填写；设计增量、锚点与审查停点开工前补齐）→ 进行中（到停点停下等放行、逐项勾验收）→ 已完成（证据齐、修正与设计偏离记录在案）

## 与其他工件的关系

- `docs/design/`：目标态——是什么、为什么这样设计
- `docs/plan/`：逐迭代的范围承诺与验收状态——做没做、验没验
- 未来 `.agents/notes/`：决策史——为什么改（AGENTS.md「修改本文件」的阈值触发时启用，不要把决策史写进本目录）

## 设计同步触发规则

变更涉及以下任一，**必须在同一迭代内同步对应设计文档**；确实暂不同步的，记入迭代文档「设计偏离」表并写明重访条件：

1. 模块 / 包结构增删改
2. 公开 API 或 seam 契约签名（Capability Seam 三角色、事件 codec 等）
3. 配置键或默认值（Profile / Bundle / Patch 可出现的键）
4. 事件 schema（Session 事件类型 / 字段）
5. 平台支持面（支持矩阵、平台链候选）
